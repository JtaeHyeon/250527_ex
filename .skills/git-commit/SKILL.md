# git-commit 스킬

## 목적

이 스킬은 AI 에이전트가 아래 규칙에 따라 Git 커밋을 수행하도록 안내합니다.

- 변경 사항을 **논리적 단위로 잘게 나눠** 커밋한다 (파일 단위 또는 기능 단위).
- 커밋 메시지 형식: `<타입>: <한글 설명>`
- 모든 커밋이 완료되면 `git push origin main`으로 원격에 푸시한다.

---

## 커밋 타입 (영어)

| 타입       | 사용 시점                                      |
|------------|------------------------------------------------|
| `feat`     | 새로운 기능 추가                               |
| `fix`      | 버그 수정                                      |
| `docs`     | 문서 작성 또는 수정 (README, AGENTS.md 등)     |
| `style`    | 코드 포맷팅, 세미콜론 누락 등 기능 변경 없음  |
| `refactor` | 리팩터링 (기능 변경 없이 코드 구조 개선)      |
| `test`     | 테스트 코드 추가 또는 수정                     |
| `chore`    | 빌드 설정, 패키지 관리, 기타 잡무             |
| `asset`    | 이미지, SVG 등 에셋 파일 추가·수정            |

---

## 커밋 메시지 형식

```
<타입>: <한글로 작성한 변경 내용 요약>
```

**예시**:
```
docs: AGENTS.md에 행동 지침 초안 작성
feat: 로그인 페이지 UI 추가
fix: 버튼 클릭 시 이벤트 미동작 수정
asset: 고양이 SVG 아이콘 추가
```

---

## 에이전트 실행 절차

1. `git status`로 변경된 파일 목록을 확인한다.
2. 변경 파일을 **논리적으로 그룹화**한다.
   - 예: 설정 파일 / 소스 파일 / 에셋 파일은 각각 별도 커밋
   - 같은 기능에 속하는 파일은 한 커밋으로 묶어도 됨
3. 각 그룹별로 `git add <파일>` → `git commit -m "<타입>: <한글 설명>"` 을 수행한다.
4. 모든 커밋 완료 후 `git push origin main`을 실행한다.
5. 각 커밋에 대해 **무엇을 / 왜 / 어떤 결과**인지 사용자에게 설명한다.

---

## 주의 사항

- `.DS_Store`, `Thumbs.db`, `node_modules/` 등 불필요한 파일은 커밋하지 않는다.
- 커밋 하나에 너무 많은 변경을 담지 않는다 (단일 책임 원칙).
- 타입은 반드시 **영어 소문자**로, 설명은 반드시 **한글**로 작성한다.
- `git push` 전에 `git log --oneline -5`로 커밋 목록을 확인하는 것을 권장한다.
